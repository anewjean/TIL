    * **PR 쪼개기**
        * [0]e8ad782, [1]f01cd80, [2]1d24adf, [3]432sf32, [4]14dskas, [5]a9d3245, [6]3wa0fjn2, ... 이런 커밋들로 PR을 생성했는데 범위가 너무 컸다.  
        * 따라서 [2]1d24adf, [5]a9d3245를 기준으로 브랜치를 새로 생성해서 `e8ad782, f01cd80` / `1d24adf, 432sf32, 14dskas` / `a9d3245, 3wa0fjn2` 3개 PR로 나눴다. 
        * 처음에 git checkout -b <새로운 브랜치 명> <커밋 해시> 해서 1d24adf로 이동했는데 `warning: refname '1d24adfab8adcdd16741ef480b0892c5d15a58c3' is ambiguous. Git normally never creates a ref that ends with 40 hex characters because it will be ignored when you just specify 40-hex.`이런 경고메세지가 떴고 [0] 부터 [6]까지 로그가 다 나왔다. 
        * 그 이유는 해시처럼 생긴 이름의 ref가 Git 내부에 존재해서, Git이 이게 진짜 커밋인지, 아니면 브랜치나 태그 같은 ref 이름인지 모르는 상황이기 때문이다. 
        * 따라서 git checkout -b deploy_ec2 1d24adf^**{commit}** 이렇게 명령하니까 1d24adf 커밋이 최신인 브랜치로 제대로 생성되었다.
    * **배포 서버에 올린 시드데이터 넣으니까 동작하는 api가 다수 미동작**
        * 로그 분석 결과 데이터 정합성 문제 
            * GROUP BY를 쓰면서 SELECT할 컬럼을 모두 명시하지 않았다. `ONLY_FULL_GROUP_BY`가 비활성화되지 않은 상태라면 따로 에러가 나지 않는데 새로 배포한 서버의 MySQL은 `ONLY_FULL_GROUP_BY`가 활성화된 상태였다. 따라서 GROUP BY를 삭제하고 DISTINCT로 변경했다. 집계 쿼리가 아닌 이상 중복을 제거 하고 싶을 때는 DISTINCT가 권장된다고 한다.

    * **팀원 한명만 로그인 시 크롬에서 400에러 발생**
        * 같은 코드인데 내가 `curl -i -X OPTIONS http://localhost:8000/api/workspaces/1/tabs \  -H "Origin: http://localhost:3000" \ -H "Access-Control-Request-Method: GET"` 명령을 실행한 결과
            * Access-Control-Allow-Origin 값이 `프론트 주소`로 특정됨
            ![](./정글(25.03.10~25.07.31)/images/Access-Control-Allow-Origin.png)
        * 크롬에서 400 에러 발생하는 팀원의 결과
            * Access-Control-Allow-Origin 값이 `*` 
            ![](./정글(25.03.10~25.07.31)/images/Access-Control-Allow-Origin_error.png)
        * CORS 스펙 상 `Access-Control-Allow-Origin: *` 은 `withCredentials: true` 와 함께 사용할 수 없기 때문이다.
        * 그런데 분명히 이렇게 CORS를 설정해주고 있었다.
            ![](./정글(25.03.10~25.07.31)/images/CORSmiddleware.png)
        * 그리고 캐시가 없는 시크릿모드로 들어가보니 정상 작동해서 캐시를 초기화해서 해결했다.
